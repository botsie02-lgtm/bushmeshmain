# Radio voice assistant — foreground offline boundary

Selected: existing Android API 31+ createOnDeviceSpeechRecognizer, one fresh recognizer per explicitly initiated turn; en-AU requested, no default/network recognizer fallback. Availability is not proof that the Australian model is installed or accurate. TTS selects advertised installed non-network English voices, preferring en-AU; no cloud voice fallback. Android services are supplied by the device, not bundled or audited speech engines. Model provisioning may require internet/system settings. No recordings retained or uploaded by BushMesh. No transcript/coordinate logging. Native audio focus and lifecycle cancel recognition on pause, timeout, permission failure and critical speech. Ordinary speech cannot start while recognition or critical speech is active. No microphone startup on boot.

The application singleton is independent of component mounting. VoiceDestination is an explicit adapter; future Convoy must supply an independently authorised operational destination, never the viewed Radio scope. Radio captures full scope and session epoch, rechecks UI scope, foreground and connection epoch, uses existing exact readback + durable journal + final guard. No old direct-carrier PTT send (compatibility component now readiness only). Dormant protocol voice pipeline is not the Radio execution path. Radio acceptance is not peer delivery. No uncertain retry. Quick phrases use existing library; optional automatic grant applies to one explicitly chosen existing template for one next command, exact match, high confidence, same scope/epoch and current library check. Ordinary dictation only appends to draft. No key/reveal/destructive actions. No location disclosure: legacy automatic gate remains false. Local speed/heading only with native provider identity, precise permission, valid nonfuture fix <=15s, accuracy <=50m, heading only at speed >=5 km/h. GPS heading is course of travel not compass orientation.

Wake-word research: Android SpeechRecognizer docs explicitly reject continuous recognition as intended use (https://developer.android.com/reference/android/speech/SpeechRecognizer). Vosk 40 MB small US-English model Apache-2.0 (https://alphacephei.com/vosk/models); not an Australian accuracy guarantee. sherpa-onnx Apache-2.0 runtime and Android keyword spotting (https://github.com/k2-fsa/sherpa-onnx); separately verify specific model weights/license, size and commercial redistribution. openWakeWord included pretrained weights CC BY-NC-SA 4.0 (https://github.com/dscripka/openWakeWord); not acceptable as a default commercial redistributable model. Dedicated detector could be low-power relative to continuous full ASR, but no CPU/battery/false wake or vehicle-noise measurements yet. No new speech dependencies or wake model. Android microphone FGS requires explicit visible activation, RECORD_AUDIO, service type/permission and notification (https://developer.android.com/about/versions/14/changes/fgs-types-required); audio focus requires top app/FGS for target API35+ (https://developer.android.com/media/optimize/audio-focus). Future separate microphone service must not change existing BLE owner or start on boot. Background/screen-off capture and persistent cross-tab listening are not implemented. Foreground finite dialogue is hands-free between explicit start and result; no actual wake detection, no continuous listening toggle. Recognition errors fail closed. Voice rate/selection, partial results, hold-to-talk and custom aliases not yet complete. Auto-read during active recognition is not spoken; history and unread preserved. Native notification policy unaffected.

Physical test: install models before leaving coverage; airplane mode (Bluetooth manually enabled as needed), en-AU, denied permission then retry, audio focus interruption, critical alert during listening, car noise/BT routing, background/tab transition, two radios, rekey during confirmation, no/yes, oversized dictation, capacity failure, uncertain radio outcome. Do not confuse fake recognition tests with physical accuracy. Preserve all existing CI and physical gates.
