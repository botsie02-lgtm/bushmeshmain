# Verified convoy telemetry v1 — Wave 4 integration handoff

**Branch:** feature/verified-convoy-telemetry-v1  
**Immutable base:** ca3388e54deafbe5e6bc854c1a145873a1508d01  
**Status:** reusable fail-closed feature components only. **NOT production activated.**

## What exists

- contracts.ts: explicit authority, source-node binding, monotonic sequence, airtime, canonical runtime and optional protected checkpoint ports. There is deliberately NO default live authority, radio, key, node binding or transmission setup.
- cadence.ts: source-scoped Android fix validation (30 s fix age, maximum 5 s future skew, <=100 m accuracy, valid lat/lon/speed/heading). Conservative 30 s minimum send interval, 180 s stationary heartbeat, 50 m movement / 30 degree heading criteria, six queued updates per rolling ten minutes. GPS loss generates a one-time location-unavailable heartbeat only after an earlier successfully queued fix; recovery requires a fresh Android fix.
- VerifiedConvoyTelemetry.ts: accepts only canonical runtime accepted protected-group Convoy frames. Extracts sender device ID, epoch and authenticated routing node from the SAME validated protected-group container. It checks the canonical authenticated header, exact Security group, current epoch, convoy ID, node ID, sender device binding, role/order, freshness, sequence wrap-aware monotonicity, member active state and valid absolute position. It rejects unauthenticated location deltas rather than trusting a missing anchor. On group/member/identity/revision invalidation all stored coordinates and outbound cadence are purged.
- project(): independently re-resolves verified active membership every call, excluding the local vehicle and removed members, returning a bounded (<=32) authorised ConvoyMapMember[] plus missing-position/recent/stale/disconnected presence labels. This is **local reception freshness**, not proof of a remote radio connection or remote acknowledgement.
- publish(): uses canonical Protocol v1 encodeBushMeshConvoyWire and calls ONLY the existing runtime service's prepareAndQueue() with trafficClass=convoy-group, authenticated group/source routing, group association, no blind retries, short expiry and ackRequested=false. The result is called **queued-locally**, never delivered.
- restore(): optional private historical coordinate checkpoint. It requires a caller-provided, authenticated, durable, protected store, current active roster revalidation and matching exact epoch/identity/roster binding. Snapshot data is never membership proof or a replay-root. Without that store, an app restart safely shows all remote positions as missing until fresh authenticated reception. A changed group epoch invalidates recovery.

## Formal activation gate — mandatory, currently unresolved

1. **Production Android Security keys/stores.** Install independently validated durable Security v1 identity, group symmetric key, nonce/replay and protected metadata providers. The existing in-memory WebCrypto tests are NOT hardware-backed deployment evidence. No position transmission or receipt is authorised by test cryptography.
2. **Current signed/authoritative membership and node binding.** Wave 4 must implement VerifiedTelemetryAuthority.resolveActiveRoster() from a real active convoy, a live independently verified Security group/key/epoch, current pinned member fingerprints/trust and an authenticated, collision-free DeviceIdentity.deviceId <-> 32-bit Protocol v1 sourceNodeId mapping. Security v1 GroupRecord has no source node binding and the Wave 3 Security v2 proposals are review-gated. A local map of MeshCore contacts or invitation metadata cannot satisfy this.
3. **Trust/identity/epoch invalidation subscription.** The authority MUST purge immediately on local identity rotation, peer revocation, group epoch change, active convoy change and source mapping changes, and re-verify at EVERY read/send/accept. Implement subscription backed by genuine security transactions, not a UI event or unverified registry snapshot.
4. **Durable protocol counters.** Provide TelemetrySequencePort next() with per-local-device monotonic Protocol v1 convoy sequence and messageId allocation across process death. Reusing a reset counter causes legitimate traffic to be dropped by remote sequence/dedup guards. Frozen Security v1 nonce counters are NOT this protocol sequence allocator.
5. **Airtime/duty-cycle admission.** Implement TelemetryAirtimePort using the existing transport's real payload budget and location duty cycle, including group-container ciphertext overhead and queue congestion. The feature's own bounded cadence is necessary but not sufficient.
6. **Strict canonical integration wiring.** Bind to BushMeshV1RuntimeService.subscribeInboundResults() (never raw carrier bytes) and prepareAndQueue(), with application lifetime singleton ownership and verified foreground Android GPS fixes read from LocationSessionProvider. Do not modify or replace the canonical runtime, native radio, map tile reader, Security v1, Protocol v1, or GPS owner. Pass project().mapMembers to ConvoyMap only while the active authorised convoy matches its convoyId. Isolate simulation fixture injection to Jest.
7. **Verified epoch and packet provenance.** The runtime currently returns authenticated group routing, but not the senderDeviceId/key epoch in its typed result. This feature reads them from the validated same protected-group container after an accepted runtime result. Formal review must verify this provenance holds across fragmentation, forwarding and background replay and that immutable decoded results cannot be forged by other application producers. A future reviewed runtime metadata extension may eliminate re-decoding the container.
8. **Security v2 revocation/rejoin convergence.** Frozen v1 cannot atomically enrol incremental members or distribute and acknowledge new keys across disconnected vehicles. The Wave 3 v2 design is not approved. Do not project removed members, or treat old group keys as current, until transaction/epoch convergence is implemented and reviewed.
9. **Sender-fix timestamps.** Protocol v1 Convoy wire carries sequence, position and optional heading but **NO GNSS fix timestamp**. The sender verifies the native fix age before queuing and the receiver rejects old/future **local receipt timestamps**. The receiver cannot cryptographically prove the age of the origin GPS fix after delayed store-and-forward delivery. Do not claim end-to-end GNSS sample freshness without a reviewed additive protocol extension. This implementation disables store-and-forward for live outgoing position and rejects receipt age over 90 s.
10. **Queue/restart and physical validation.** Full Jest + TypeScript + lint + Android debug builds, multi-phone field testing of Security v1 replay state over process death, authenticated node binding across reconnect/rotation, actual duty cycle, real radio path, current-key rekey across 2/5/20 devices and map privacy review are mandatory before lifting the disabled activation gate.

## Wave 4 integration steps

1. Implement and security-review VerifiedTelemetryAuthority. Derive the active convoy from ActiveOperationalConvoyProvider + AuthorizedConvoyDirectory and the group epoch/key from the actual Security managers. Include trusted roster node assignments from a reviewed authenticated authority; reject collisions, unknown node IDs and stale fingerprints.
2. Supply audited monotonic TelemetrySequencePort, actual AirtimePort, and the real BushMeshV1RuntimeService runtime port. Test the entire security-to-runtime pipeline on real phones; avoid using fake group-container packets outside unit tests.
3. Construct one VerifiedConvoyTelemetry service per runtime profile; bind mandatory invalidation callbacks, incoming accepted-result stream and genuine Android latestFix readings. Explicitly dispose on profile changes. Do not start live publishing unless all activation prerequisites are proven.
4. Map integration reads await project(). It must independently verify active convoy identity before rendering authorisedMembers. Keep the existing selfFix separate, and never feed MeshCore contacts, legacy convoy tracker results or unprotected packets to map members.
5. If restart recovery is necessary, use a verified integrity-protected, crash-durable app-private store for checkpoints. If unavailable, show missing-position states until new authenticated data arrives. Position checkpoints are personal location information; do not export or log them by default.
6. Conduct peer reviews and real-radio negative testing, including group epoch rotations, revoked members and offline/reconnected phones. Only a separately approved activation change may install the live authority/radio/GPS connectors.

## Security limits of unit tests

The tests build syntactically canonical fake encrypted-group containers and manually construct a runtime accepted-result fixture. This tests the feature boundary and negative identity conditions; it is NOT proof of cryptographic decryption, actual sender possession, Security v1 replay durability, genuine node-binding authentication, hardware key protection, remote delivery, duty-cycle compliance or Android GPS provenance.

**No changes** were made to main, integration branches, AppShell, Android radio, Security v1, Protocol v1, the GPS owner, or offline map tile rendering.
